# Токен F1TV для живого экрана

Без токена живой поток F1 отдаёт только тайминг. С токеном (подписка F1TV) появляются позиции
машин на карте и телеметрия: скорость, газ, тормоз, передача, обороты.

Токен — секрет. Его нельзя коммитить, присылать в чат и печатать в логах.
Живёт он около четырёх дней, поэтому перед гоночным уикендом его нужно обновлять.

## Где он лежит

| Где | Путь |
|---|---|
| На вашей машине (после входа) | `~/Library/Application Support/fastf1/f1auth.json` |
| На сервере | `/opt/lap-vision/shared/f1-secrets/f1auth.json` |
| В контейнере `lapvision-f1-*` | `/run/f1-secrets/f1auth.json` (только чтение) |

Каталог `f1-secrets` создаёт и монтирует `deploy/deploy_f1.sh`, путь к файлу передаётся сервису
через `LAP_VISION_F1_F1TV_TOKEN_FILE`. Монтируется каталог, а не файл: заменённый на хосте файл
виден контейнеру сразу, без передеплоя.

## 1. Получить токен (на вашей машине)

1. Войдите на f1.com / F1TV в браузере, где установлено расширение FastF1 для входа.
2. В терминале (из каталога сервиса) запустите:

   ```bash
   cd ~/py/lap-vision-f1
   .venv/bin/python -c "from fastf1.internals.f1auth import get_auth_token; get_auth_token()"
   ```

   Команда поднимает локальный сервер и ждёт, пока расширение пришлёт токен. Когда токен придёт,
   процесс завершится сам. Пока он висит, файл пустой.
3. Проверьте, что файл не пустой и токен действителен (сам токен команда не печатает):

   ```bash
   ls -la ~/Library/Application\ Support/fastf1/f1auth.json
   cd ~/py/lap-vision-f1 && .venv/bin/python - <<'EOF'
   from pathlib import Path
   from app.services.live import token_status
   print(token_status(Path.home() / "Library/Application Support/fastf1/f1auth.json"))
   EOF
   ```

   Ожидаемо: `mode: 'f1tv'`, `expired: False` и срок в `expires_at`. Если `mode: 'anonymous'` или
   размер файла 0 — вход не завершился, повторите шаг 2.

## 2. Скопировать токен на сервер

В кавычках `~` не раскрывается, поэтому используйте `$HOME`. Копируем во временное имя и
переименовываем, чтобы сервис никогда не прочёл недописанный файл.

```bash
SRC="$HOME/Library/Application Support/fastf1/f1auth.json"
DEST=/opt/lap-vision/shared/f1-secrets

scp "$SRC" ubuntu@95.179.154.60:$DEST/f1auth.json.new
ssh ubuntu@95.179.154.60 "chmod 644 $DEST/f1auth.json.new && mv $DEST/f1auth.json.new $DEST/f1auth.json"
```

Права 644, потому что контейнер читает файл не от вашего пользователя. Каталог доступен только
администраторам сервера, файл по сети наружу не отдаётся.

Первый раз каталог `f1-secrets` появится после деплоя F1-сервиса с обновлённым `deploy_f1.sh`.
До этого его можно создать руками: `ssh ubuntu@95.179.154.60 "mkdir -p /opt/lap-vision/shared/f1-secrets"`.

## 3. Проверить на сервере

```bash
ssh ubuntu@95.179.154.60 "ls -la /opt/lap-vision/shared/f1-secrets; docker exec lapvision-f1-green ls -la /run/f1-secrets"
```

(имя контейнера — `lapvision-f1-green` или `lapvision-f1-blue`, смотрите `docker ps`.)

В интерфейсе: на странице F1 live в шапке метка **«F1TV: map and telemetry»** означает, что токен
подхвачен; метка **«Timing only»** — что рекордер идёт без токена.

## Важно: токен читается при подключении рекордера

Рекордер читает файл один раз, когда открывает соединение с лентой F1. Поэтому:

- заменили токен между сессиями — следующая запись (автоматическая, за 15 минут до старта)
  подхватит новый;
- заменили токен, когда запись уже идёт — она продолжит с прежним. Чтобы перейти на новый, в
  админке на странице F1 live нажмите «Stop recording» и снова «Start recording». Накопленное
  не теряется: файл записи дописывается, состояние восстанавливается из него.

## Когда обновлять

- За день до гоночного уикенда, а лучше за два: токен живёт около четырёх дней.
- Срок окончания видно в `expires_at` (шаг 1.3). Токен, скопированный на сервер, имеет тот же срок.
- Просроченный токен рекордер воспринимает как отсутствие: запись идёт в режиме «Timing only».

## Если что-то не так

| Симптом | Причина и что делать |
|---|---|
| Файл на машине 0 байт | Вход не завершился. Запустите команду из шага 1, дождитесь завершения процесса. |
| `mode: 'anonymous'` после копирования | Скопирован пустой файл или нет подписки F1TV на этом аккаунте. |
| В интерфейсе «Timing only» при свежем токене | Запись была запущена до замены токена. Перезапустите запись (раздел выше). |
| Сервер возвращает 403 на подключение | Это блокировка IP сервера, а не токен. Рекордер должен идти через домашний прокси (`f1-proxy-relay`), проверьте, что прокси включён. |
| `scp: Permission denied` | Нет прав на каталог. Каталог создаётся деплоем от `ubuntu`; проверьте владельца: `ls -ld /opt/lap-vision/shared/f1-secrets`. |

## Дополнительно (необязательно)

Если старая живая панель на странице сессии не нужна, выключите полный разбор записи, который
нагружает процессор на длинной гонке: переменная GitHub Actions `F1_LIVE_SNAPSHOT=false`.
Подробности — в комментарии у `F1_LIVE_SNAPSHOT` в `.github/workflows/deploy-blue-green.yml`.
