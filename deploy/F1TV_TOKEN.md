# Токен F1TV

Без токена (подписка F1TV Access/Pro) живой поток F1 отдаёт только тайминг, а архив
`livetiming.formula1.com/static` с середины октября 2026 не отдаёт ничего (401). С токеном
появляются позиции машин на карте, телеметрия и загрузка прошедших сессий.

Сервис получает токен сам: входит в аккаунт F1 по email и паролю (FastF1 ≥ 3.9, OAuth через
`id.formula1.com`, без браузера). Токен живёт около четырёх дней и не продлевается. Пароль, токен —
секреты: их нельзя коммитить, присылать в чат и печатать в логах.

## Когда сервис входит

- **Перед первой сессией этапа.** Когда бекенд запускает рекордер для этапа впервые (обычно FP1 в
  пятницу), сервис входит заново, каким бы ни был срок текущего токена. Новый токен живёт до
  вторника-среды, то есть весь уикенд, и во время гонок сервис не входит ни разу. Следующие сессии
  того же этапа (квала, спринт, гонка) вход не вызывают. Рекордер вход не ждёт: подключается с
  тем токеном, что есть, а если токена не было — переподключается, когда он появится.
- **Страховка между уикендами:** если токена нет, он истёк или до конца меньше 12 часов. Для токена,
  полученного в пятницу, это случается уже после гонки. Нужно для загрузки прошедших сессий.
- **Не чаще раза в 30 минут**, удачно или нет: неверный пароль не повторяется в цикле. Старый токен
  при неудаче продолжает использоваться, пока не истечёт; вход для уикенда остаётся в ожидании
  (`sign_in.pending: true`) и повторяется.

## Как это устроено

- Входит только основной процесс сервиса (`F1TVAuth.run`, проверка раз в минуту и сразу по запросу
  от рекордера), в отдельном короткоживущем процессе: не в пуле воркеров, где вход ждал бы
  многоминутную загрузку сессии.
- Вход идёт через SSH-туннель на домашнее устройство (`make tunnel`, `f1-proxy-relay`), как и все
  запросы к F1: IP сервера F1 блокирует. На сервере (`LAP_VISION_F1_F1TV_REQUIRE_PROXY=true`)
  напрямую сервис не входит никогда: пока туннеля нет, он ждёт (`last_error: waiting for a proxy`)
  и входит в течение минуты после того, как `f1-proxy-relay` зарегистрирует туннель. Без туннеля
  сервер всё равно ничего не получает от F1, так что запаса по сроку токена на этот случай не нужно.
- Если туннелей несколько, следующий пробуется, только если через предыдущий F1 не ответил.
  Неверный пароль через другие туннели не повторяется: это серия неудачных входов в аккаунт.
- Токен сохраняется в файл в формате FastF1. Воркеры (история) и рекордер (live) только читают его
  и сами не входят никогда: иначе при истечении токена все процессы вошли бы разом. Пароль в эти
  процессы не передаётся.
- Рекордер, уже подключённый с токеном, при обновлении токена не перезапускается: соединение живёт
  дольше токена, а перезапуск посреди сессии — дыра в данных. Если соединение упадёт, рекордер
  поднимется уже с новым токеном.
- Если вход не работает, используется токен, положенный руками (`f1auth.json`, см. ниже).

| Что | Где |
|---|---|
| Логин/пароль | GitHub Secrets `F1_USERNAME`, `F1_PASSWORD` → на сервере `/opt/lap-vision/f1tv.env` (600) → `--env-file` контейнера |
| Токен, полученный сервисом | сервер: `/opt/lap-vision/shared/f1tv/f1tv-token.json`; контейнер: `/var/lib/lap-vision-f1/f1tv/f1tv-token.json`; локально: `var/f1tv-token.json` |
| Токен, положенный руками (запасной) | сервер: `/opt/lap-vision/shared/f1-secrets/f1auth.json`; контейнер: `/run/f1-secrets/f1auth.json` (только чтение) |

## Настройка (один раз)

1. В GitHub → Settings → Environments → `production` → Secrets добавьте `F1_USERNAME` (email
   аккаунта F1) и `F1_PASSWORD`.
2. Задеплойте сервис. `deploy_f1.sh` запишет `f1tv.env` и подключит каталог токена.
3. Проверьте, что сервис вошёл (сам токен не возвращается):

   ```bash
   ssh ubuntu@95.179.154.60 "docker exec lapvision-f1-green python -c \"import os, urllib.request as u; print(u.urlopen(u.Request('http://127.0.0.1:%s/v1/f1tv/status' % os.environ['LAP_VISION_F1_PORT'], headers={'X-Internal-Token': os.environ['LAP_VISION_F1_INTERNAL_TOKEN']})).read().decode())\""
   ```

   (имя контейнера — `lapvision-f1-green` или `lapvision-f1-blue`, смотрите `docker ps`.)

   Ожидаемо: `"mode": "f1tv"`, срок в `expires_at`, `"sign_in": {"enabled": true, "pending": false, ..., "last_error": null}`.
   Если туннель в момент деплоя не подключён — `last_error: waiting for a proxy`, это нормально.
   Неудачный вход пишется в логи контейнера предупреждением `f1tv: sign-in failed: ...`.

В интерфейсе: на странице F1 live в шапке метка **«F1TV: map and telemetry»** означает, что токен
есть; **«Timing only»** — что рекордер идёт без токена.

## Локально

Добавьте в `.env.local` (он в `.gitignore`):

```
F1_USERNAME=you@example.com
F1_PASSWORD=...
```

Сервис войдёт при старте и сохранит токен в `var/f1tv-token.json`.

## Если что-то не так

| Симптом | Причина и что делать |
|---|---|
| `sign_in.enabled: false` | Нет логина/пароля в контейнере. Проверьте секреты и `/opt/lap-vision/f1tv.env`, передеплойте. |
| `last_error: ... Sign-in was rejected` | Неверный email или пароль. Исправьте секрет и передеплойте. |
| `last_error: waiting for a proxy` | Ни один туннель не подключён. Включите `make tunnel` на домашнем устройстве; проверьте `journalctl -u f1-proxy-relay`. Без туннеля не работает ничего, не только вход. |
| `sign_in.pending: true` долго | Вход для уикенда не проходит: смотрите `last_error`. Рекордер тем временем пишет со старым токеном, если он ещё действует. |
| `last_error` с 403/таймаутом или про страницу входа | F1 включил защиту от ботов или туннель не пропускает. Проверьте `f1-proxy-relay`; на время положите токен руками (ниже). |
| `last_error: ... no subscription token` | На аккаунте нет активной подписки F1TV. |
| Сервер возвращает 403 на подключение рекордера | Блокировка IP сервера, а не токен. Рекордер должен идти через домашний прокси (`f1-proxy-relay`). |

## Запасной вариант: токен руками

Если вход по паролю сломался (F1 поменял страницу входа или включил защиту), токен можно получить
в браузере через расширение FastF1 и положить на сервер. Сервис возьмёт его, когда своего
действующего токена нет.

1. На своей машине (нужен браузер с расширением FastF1 для входа):

   ```bash
   cd ~/py/lap-vision-f1
   .venv/bin/python -m fastf1 auth f1tv --authenticate --method browser
   ```

   FastF1 сохранит токен в `~/Library/Application Support/fastf1/f1auth_token.json` (JSON, поле `value`).

2. Скопируйте на сервер только сам токен, через временное имя:

   ```bash
   DEST=/opt/lap-vision/shared/f1-secrets
   .venv/bin/python -c 'import json,pathlib; print(json.loads((pathlib.Path.home()/"Library/Application Support/fastf1/f1auth_token.json").read_text())["value"])' \
     | ssh ubuntu@95.179.154.60 "cat > $DEST/f1auth.json.new && chmod 644 $DEST/f1auth.json.new && mv $DEST/f1auth.json.new $DEST/f1auth.json"
   ```

   Права 644, потому что контейнер читает файл не от вашего пользователя.

## Дополнительно (необязательно)

Если старая живая панель на странице сессии не нужна, выключите полный разбор записи, который
нагружает процессор на длинной гонке: переменная GitHub Actions `F1_LIVE_SNAPSHOT=false`.
Подробности — в комментарии у `F1_LIVE_SNAPSHOT` в `.github/workflows/deploy-blue-green.yml`.
